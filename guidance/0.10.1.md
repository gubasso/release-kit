## What changed

After a pin move, the `rk upgrade` preview from a newer binary and the version gate route the reader through the setup skill of the new rk. The managed block of `AGENTS.md` carries the same route as one more bullet. The block grows by one line. An `AGENTS.md` near its line budget loses that line of room.

`rk integrate <branch>` judges the version gate against the record at the tip of the branch, not the record in the working tree of the target, because the integration makes the branch record the trunk's. So a pin-move branch that carries its `rk upgrade` integrates from the main checkout with the rk of the worktree's devshell: `direnv exec <worktree> rk integrate <branch> --target <main checkout>`. An older rk in the main checkout refuses and names that command. A branch with no record at its tip falls back to the record of the target. An rk before 0.10.1 judges the trunk record, so its route stays `rk integrate <branch> --target .` from inside the worktree. This change needs no step.

## What to do

1. After the pin move, load the devshell and run the upgrade through the rk-setup skill of the rk in that devshell, and do every migration it names. Before `rk upgrade`, read it with `rk skill show rk-setup`. After it, the project's .claude/skills/rk-setup is that skill. Never use a host copy or an older skill.
2. Run `rk upgrade --target . --apply`. It adds the bullet to the managed block of `AGENTS.md` and refreshes the skill files.
3. If the line budget of `AGENTS.md` fails, shorten the project's own text outside the managed block.
4. Commit the files with the receipt.
