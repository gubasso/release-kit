# release-kit 0.9.2

- destinations: release-plz.toml
- action: operator-step

## What changed

The seeded `release-plz.toml` of both Rust pairs no longer carries a `[changelog]` section. Earlier seeds pinned a `header` that restated release-plz's default text with its last sentence on one line, so that a reflowing markdown formatter and the next release agreed on it. release-plz now writes its native changelog, and the target's checks leave that file alone instead: the release tool writes `CHANGELOG.md`, so every formatter and prose gate of the target excludes it, as the binding of the target's technology says.

## What to do

`release-plz.toml` is seeded, so the target owns it and an upgrade does not change it. Delete the `[changelog]` section that holds the pinned `header`, with its comment, from `release-plz.toml`. Keep any `[changelog]` key the project added for a reason of its own. Then exclude `CHANGELOG.md` from every formatter and prose gate of the target, as "Generated files" in `bindings/README.md` lists, and commit both changes together. From then on, release-plz writes the changelog in its native form, and no check of the target rewrites it.
