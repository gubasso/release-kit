# release-kit 0.7.0

- destinations: .release-kit/config.toml, .release-kit/manifest.json, .gitlab-ci.yml, .gitlab/ci/mr-title.yml
- action: landing-write

## What changed

The committed answers are now one target configuration typed by the domain that owns each answer, and the record states the same domains.

`.release-kit/config.toml` moves to `schema_version = 2`. The project profile states what the project is: `profile.technologies` carries zero or many technologies, `profile.forge` is optional, and `[profile.release]` states the intent as `automatic`, `external`, or `none`, with the driver, style, and line prefix belonging to an automatic release alone. `[git]` states the trunk and the checkout mode. `[capabilities]` states the optional products the target requests. `[security]`, `[setup]`, and `[protection]` keep their own tables.

The keys moved as follows. `project.tech` became `profile.technologies` and the automatic release driver. `project.forge` became `profile.forge`. `project.trunk` became `git.trunk`. `landing.workflow` became `git.checkout_mode`, and its two values renamed: `worktree` is `linked-worktree` and `branches` is `main-worktree`. `landing.style` became `profile.release.style`. `setup.line_prefix` became `profile.release.line_prefix`. `landing.nix` became `capabilities.nix_packaging`, and `landing.scorecard` and `landing.code_scanning` moved under `[capabilities]` unchanged. `capabilities.reporting_policy` is new and reads as `true` for a target that already landed the policy.

The receipt moves to schema 9 and states the same domains: `profile`, `git`, `capabilities`, and the render parameters no domain owns. A receipt at schemas 1 through 8 reads through one bounded conversion, and the first landing rewrites it.

The flags follow the domains. The canonical names are `--technology`, repeatable; `--forge`; `--repo`; `--release-mode`; `--release-driver`; `--release-style`; `--trunk`; `--checkout-mode`; `--nix-packaging`; `--reporting-policy`; `--scorecard`; and `--code-scanning`. `--tech`, `--style`, `--workflow`, and `--nix` still work as hidden aliases, and `--workflow worktree` and `--workflow branches` still read.

`rk profile` is new. It reports every resolved value with the source that answered it, the categories this release does not know, what the observation proposed, and which capabilities the catalog selects with the destinations they land. It writes nothing and judges nothing.

A landing now derives from the whole configuration through a capability catalog, so a repository with no technology, no forge, or no release is a valid target: it receives the local Git workflow guards and nothing it cannot run. A GitLab target that releases nothing receives a complete title gate, which is the fragment plus a minimal root pipeline that includes it; where the target owns `.gitlab-ci.yml`, the fragment lands and the activation is the one `include` line the report names.

Every machine report's schema moves with the shape: `rk.init/10`, `rk.upgrade/10`, `rk.adopt/10`, `rk.status/12`, `rk.stage/4`, `rk.assess/4`, `rk.issue-start/2`, and the new `rk.profile/1`.

Every landed byte is unchanged. The checkout mode's rename is a configuration and record word: the routing block, the hook block, the hook ids, and the CI sweep pair render exactly as they did.

## What to do

Run the upgrade and commit the two records:

```bash
rk upgrade --target . --apply
```

The configuration migrates in place. A comment you wrote travels with its value; a comment the template wrote is refreshed, because a key whose vocabulary moved would otherwise stand beside a sentence describing the key it replaced.

Read the result before you commit it:

```bash
rk profile --target .
```

A GitLab target takes one new destination where it releases nothing: the minimal root pipeline that activates the title gate. Where you already own `.gitlab-ci.yml`, nothing overwrites it, and the report names the `include` line to add.

A script that calls `rk` by its older flags keeps working. To move it, read `rk usage`: the canonical names are the ones above.
