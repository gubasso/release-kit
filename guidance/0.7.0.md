# release-kit 0.7.0

- destinations: .github/workflows/scorecard.yml, .release-kit/config.toml, .release-kit/manifest.json
- action: operator-step

## What changed

This release adds one opt-in landing capability and moves the receipt to schema 8.

`rk init --scorecard` lands `.github/workflows/scorecard.yml` on a GitHub target. The workflow computes an OpenSSF Scorecard result and publishes it to the public Scorecard API. The capability is off by default, because a run posts to a public API and reads repository metadata.

The receipt gains one parameter, `scorecard`. A receipt written by an earlier release names no such parameter and reads as the opt-out, so an upgrade adds no workflow the target did not request. The first successful landing rewrites the receipt at schema 8.

`.release-kit/config.toml` gains `landing.scorecard` in the `[landing]` table. An upgrade over an existing configuration inserts the key without the explanatory comment the fresh template carries.

## What to do

Nothing is required. An upgrade records the opt-out and lands no new file.

To take the capability, run the upgrade with the flag:

```bash
rk upgrade --scorecard on --target . --apply
```

Read `rk forge github` first. It states what a Scorecard run can and cannot score under this convention, so the ceiling is known before the workflow lands.

Where the target already runs a Scorecard workflow of its own, stage the candidate and compare it with that file before the landing. Two workflows publishing one score is a collision the receipt cannot describe.

To drop the capability, run `rk upgrade --scorecard off --target . --apply`. The destination leaves the receipt and the file stays on disk as the project's own.
