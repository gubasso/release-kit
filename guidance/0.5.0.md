# release-kit 0.5.0

- destinations: dist-workspace.toml, flake.nix
- action: operator-step

## What changed

release-kit supports one platform: x86_64 GNU/Linux. The seeded `dist-workspace.toml` now declares one release target, `x86_64-unknown-linux-gnu`, and one installer, the shell installer. The seeded `flake.nix` and every dependency seed advertise one Nix system, `x86_64-linux`. release-kit itself releases, builds, and proves that one platform and no other.

Both files are seeded: a target owns and tunes them from the first landing, so an upgrade never rewrites them. A project that landed before this release keeps its five release targets, its PowerShell installer, and any second Nix system exactly as written.

## What to do

Decide which platforms your project supports. A platform your CI never builds and runs is a claim it cannot keep. Then take the step for each file your target has; a Rust target on GitLab has no `dist-workspace.toml`, because cargo-dist generates CI for GitHub Actions alone, and it takes the flake step only.

`dist-workspace.toml`, on a GitHub target: to follow the cut, edit it so `targets` names `x86_64-unknown-linux-gnu` alone and `installers` names `shell` alone, then run `dist generate` at the pinned version and commit the regenerated `.github/workflows/release.yml` with it.

`flake.nix`, on either forge: to follow the cut, edit the `systems` list down to `x86_64-linux`.

To keep a wider platform set, leave the files as they are. release-kit does not test the other platforms for you, so keep a native runner for each system your flake advertises.
