# release-kit 0.9.10

- destinations: .release-kit/config.toml, SECURITY.md
- action: landing-write

## What changed

The `[security]` table of `.release-kit/config.toml` has a new key, `scope`. It holds one paragraph that names what the project does not own and where a reporter goes instead, for example a wrapped CLI or a vendored tree. The landed `SECURITY.md` states that paragraph right after its reporting channel. The landing writes the key as `scope = ""`. An empty value renders nothing and records nothing, so `SECURITY.md` and `.release-kit/manifest.json` keep their bytes.

A landing now reports `matched` for a recorded rendered whole file that already holds the candidate's bytes, because it writes nothing there. Before, it reported `replaced`. A marked region still reports `replaced`.

## What to do

1. Run `rk upgrade --apply`. It adds `scope = ""` to `.release-kit/config.toml` and changes no other landed byte.
2. If the project states in another file what it does not own, move that paragraph into `security.scope` and run `rk upgrade --apply` again. The paragraph carries no blank line, no heading, and no `<!--` or `-->`.
3. Read `matched` in the landing report as "unchanged". Only `replaced` and `created` mean that the landing wrote the file.
