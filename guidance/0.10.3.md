# release-kit 0.10.3

- destinations: .pre-commit-config.yaml
- action: operator-step

## What changed

The managed block of `.pre-commit-config.yaml` declares the scope of its hooks with prek groups. Under the workflow guards, `no-commit-to-branch` and, in the linked-worktree mode, `rk-worktree-location` carry `groups: [local-only]`, with the reason in a comment above each. A CI checkout meets both as refusals. The comment at the top of the block no longer names a `SKIP` value. It shows the three steps that a CI job runs instead:

```bash
prek run --all-files --stage pre-commit --no-group local-only
prek run --all-files --stage pre-push --no-group local-only
prek run --all-files --stage manual --group ci-only
```

The landing writes the block. A project owns its CI workflow, so the landing changes no CI job. pre-commit prints `Unexpected key(s) present` for the `groups` key and still runs the hook. Only prek selects hooks by group.

## What to do

1. In every CI job that sets `SKIP` for the hooks, remove the `SKIP` value. Run each stage that the job runs with `--no-group local-only`, through the project's environment.
2. For each other hook id that the old `SKIP` value named, add `groups: [local-only]` to that hook in `.pre-commit-config.yaml`, with a comment above it that states why CI cannot run it.
3. For a check that only CI can run, give its hook `stages: [manual]` and `groups: [ci-only]`, and add the third step. Leave the third step out where no hook carries `ci-only`, because prek refuses a `--group` that matches no hook.
4. Make sure that `prek list --group local-only` names exactly the hooks whose comments state a reason.
5. Push, and make sure that the CI run passes.
