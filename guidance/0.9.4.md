# release-kit 0.9.4

- destinations: .release-kit/config.toml, .github/workflows/release-plz.yml, .gitlab-ci.yml
- action: operator-step

## What changed

The configuration takes a `[dev_environment]` table. It records the command prefix that runs a command in the project's own development environment, and the pinned steps or the image that put that environment on a runner. With the table, the rust release jobs run release-plz through the prefix, and install no toolchain and no release-plz themselves. With no table, every landed byte stays as it was.

## What to do

Nothing, unless the project wants its release jobs to run in its own development environment. Then write the table into `.release-kit/config.toml`, as the "The development environment" section of `rk binding rust` shows, run `<run> release-plz --version` to prove that the environment carries release-plz, and run `rk upgrade --apply`.
