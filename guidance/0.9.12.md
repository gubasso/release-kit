# release-kit 0.9.12

- destinations: .pre-commit-config.yaml
- action: landing-write

## What changed

`rk integrate` runs the pre-integrate suite with prek where prek is on `PATH`, and with pre-commit otherwise. Both runners read the same `.pre-commit-config.yaml` and take the same arguments, so the suite and the `manual` stage do not change. With neither runner on `PATH`, the gate refuses and names both.

The landed release-kit block in `.pre-commit-config.yaml` names both runners. The install comment reads `prek install --hook-type pre-commit --hook-type commit-msg --hook-type pre-push` and says that pre-commit takes the same flags. Under local integration, the integrate note names `prek run --hook-stage manual --all-files` and says that `pre-commit run` takes the same arguments. The CI sweep comment names the hook runner. Only comments in the block change. No hook, stage, or entry changes.

Two differences matter when a project moves from pre-commit to prek. prek exits 1 on a `.pre-commit-config.yaml` that declares no hook at all ("No hooks found after filtering with the given selectors"), where pre-commit exits 0. A project that carries the release-kit block always has hooks. prek sets `PRE_COMMIT_FROM_REF`, `PRE_COMMIT_TO_REF`, `PRE_COMMIT_LOCAL_BRANCH`, `PRE_COMMIT_REMOTE_BRANCH`, `PRE_COMMIT_REMOTE_NAME`, and `PRE_COMMIT_REMOTE_URL` before a pre-push run, so the landed push guards hold under either runner.
