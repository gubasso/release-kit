# release-kit 0.3.33

- destinations: GLOSSARY.md, AGENTS.md
- action: operator-step

## What changed

A target gains `GLOSSARY.md` at its root. It is a block destination, so release-kit owns the lines between its markers and every line outside them belongs to the target. The block names three terms an operator types to authorize a whole run of the workflow: `implement-and-request`, `implement-and-merge`, and `full-implement`. Each term expands to a named list of actions, and each contains the one above it. The routing block in `AGENTS.md` gains one line naming the destination and listing the terms.

The boundary is unchanged. An agent still takes no git or forge action unless the operator's request named it. A term is shorthand the operator writes for a list the operator wrote.

## What to do

Install release-kit at this version or newer. The bundle declares payload schema 2, and an engine that reads schema 1 refuses it by name rather than landing half of it: an older engine projects only the destinations it knows, so it would write the routing line naming a file it never creates. The refusal states the version to install.

Otherwise nothing. The plan carries both writes as splice operations, and a target that already keeps its own `GLOSSARY.md` keeps every line of it: the block appends at the end and later upgrades replace that region alone. To add terms of your own, write them below the end marker.
